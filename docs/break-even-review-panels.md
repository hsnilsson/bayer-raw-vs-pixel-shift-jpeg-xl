# Break-even Review Panels

The local review panels are a visual sanity check for the storage-budget
question:

```text
Does 240 MP PixelShift 16 JPEG XL preserve more useful film information than a
61 MP single-shot raw capture at the same or smaller retained size?
```

They are generated by:

```powershell
python scripts\make_break_even_review_panels.py --case-limit 999
```

Existing panel PNGs are reused by default. Pass `--force` only when the panel
layout or crop definition has changed and the existing images should be
rewritten.

Outputs are written under `results/break_even_review_panels/` and are ignored
by Git because they may contain private film scans.

## How To Read One Panel

Each panel is read from left to right:

| Tile | Meaning | What To Check |
| --- | --- | --- |
| `PS16 reference` | The rendered PixelShift 16 image state used as the comparison target. | Treat this as the codec reference, not as proof that PS16 is always visually superior. |
| `RAW61 local aligned` | The 61 MP single-shot raw render, upscaled and locally shifted for this crop. | Check whether it still looks offset, sharper only through acutance, or genuinely more detailed. |
| `PS16 JXL` | The decoded standalone JPEG XL made from the PS16 render. | Look for grain changes, banding, color shifts, halos, or texture loss. |
| `RAW61 diff x16` | Absolute difference between RAW61 and PS16, multiplied by 16. | Bright pixels mean different from PS16. This includes sampling, scaling, sharpening, registration, and render differences. |
| `JXL diff x16` | Absolute difference between JPEG XL and PS16, multiplied by 16. | This is mostly codec error. Near-black is good. Structured bright patterns are suspicious. |
| `PS16/RAW61 checker` | Alternating squares from PS16 and RAW61. | Visible jumps across square borders show remaining alignment, sharpness, color, or tone mismatch. |

The diff tiles are diagnostic. They do not prove which image is better by
themselves.

## Local Alignment

The global registration step aligns the whole RAW61 render to the PS16 render.
For review crops, the panel script also estimates a crop-local x/y shift and
prints it in the panel header:

```text
local RAW61 shift x=..., y=..., confidence=..., applied=true/false
```

This reduces false `RAW61 diff x16` signal caused by a small local offset. If
the checker tile still shows obvious jumps after local alignment, the crop
should be treated as a method-warning case rather than a clean RAW61-vs-JXL
verdict.

## Practical Scoring

Use this simple score per crop and level:

| Score | Meaning |
| --- | --- |
| `PASS` | JXL looks close to PS16, JXL diff is weak, and RAW61 does not clearly preserve more useful structure. |
| `QUESTION` | JXL changes grain/texture slightly, RAW61/PS16 alignment or acutance is ambiguous, or the crop needs another level for comparison. |
| `FAIL` | JXL shows visible color shift, banding, false texture, haloing, or clear loss of useful film detail. |

The current goal is not to prove that lossy JXL is invisible. The goal is to
find the compression range where PS16 JXL still carries more archival value
than 61 MP raw for the same storage budget.

## Interactive Review

The static panels are useful as a compact record, but they cannot pan or switch
between aligned layers. For selected public cases, generate the small static
viewers with:

```powershell
python scripts\make_break_even_review_viewers.py `
  --output-dir site\assets\review-viewers `
  --all-complete `
  --level d020 `
  --level d022 `
  --level d025 `
  --level d028 `
  --level d030
```

Open the resulting `index.html` for a crop. It supports side-by-side viewing,
a keyboard toggle that copies the right-hand candidate over the left reference,
zoom, and drag-to-pan. The viewer uses the same crop-local RAW61 alignment as
the static panel generator.
